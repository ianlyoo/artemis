# 설계

[English](design.md) · 한국어

이 문서는 Artemis가 어떻게 짜여 있고 왜 그런지 설명합니다. 각 절의 끝에는 그 생각이 `src/artemis/`의 어디에 있는지 적었습니다.

## 문제

에이전트 하나가 세션 하나에서 일하면 따라가기 쉽습니다. 한 일을 읽고 확인하면 됩니다. 문제는 한 사람이 자기 컴퓨터에서 여러 프로젝트에 걸쳐 에이전트 여럿을 부릴 때 시작됩니다.

**사람이 병목이 됩니다.** 에이전트가 모든 행동 전에 물으면, 사람은 판단할 수도 없는 것을 하루 종일 승인하다가 결국 읽지 않고 승인하게 됩니다. 아무것도 묻지 않으면 위험한 행동이 보이지 않는 곳에서 일어납니다.

**맥락이 사라집니다.** 세션마다 자기 일만 봅니다. 한 채팅에서 내린 결정은 다음 채팅에 없고, 다른 회사 모델로 바꾸면 처음부터 다시 시작합니다. 전체 그림이 남는 곳은 결국 사람의 머릿속뿐입니다.

**'끝났다'가 끝났다는 뜻이 아니게 됩니다.** 일을 한 에이전트가 끝났다고 말하는 에이전트이기도 합니다. 보고는 확인이 아닙니다.

**진짜 일에는 진짜 권한이 필요하고, 진짜 권한은 위험합니다.** 파일을 정리하고, 프로그램을 돌리고, 결과를 올리려면 사람의 컴퓨터와 키가 필요합니다. 키를 프롬프트에 붙이면 기록에 남고, 에이전트에게 셸을 주면 사람이 할 수 있는 모든 것을 주게 됩니다.

**같은 실수가 돌아옵니다.** 오늘 바로잡은 것이 다음 세션에서는 사라집니다.

Artemis는 지시를 더 붙이는 대신 구조로 답합니다. 장부 하나를 가진 홈 프로세스 하나, 대화하는 리드 한 명, 관문 하나 뒤에서 일하는 여러 회사의 작업자, 일과 분리된 판정자, 반영 경로 하나, 이름으로 쓰는 금고, 사람을 기다리는 행동의 짧은 목록, 그리고 다음 실행을 바꾸는 교훈입니다.

## 홈

Artemis는 사용자마다 늘 켜져 있는 프로세스 하나, `artemis serve`입니다. 장부를 들고, 리드와 작업자를 돌리고, 예약을 실행하고, 금고를 지키고, 앱을 서비스합니다. 홈이 가진 것은 모두 한 폴더에 있습니다. `~/.artemis`(Windows는 `%USERPROFILE%\.artemis`) 또는 `ARTEMIS_HOME`입니다. 잠금 파일이 폴더 하나에 홈 하나만 뜨게 합니다. 감독자는 그 안의 스레드로 돌기 때문에 낡아 버릴 pid 파일이 없습니다.

프로젝트는 홈 장부의 한 행입니다. Git 저장소(작업은 워크트리에서 돌고 반영 경로로 들어갑니다)이거나 아무 폴더(작업자는 Artemis 파일 도구로 일합니다)입니다. `artemis project add`로 등록하고, `--no-run`은 프로그램을 실행하는 도구를 빼고, `--root`는 작업자가 다른 폴더에도 닿게 합니다.

홈이 비정상 종료 뒤에 다시 켜지면, 열어 둔 채 남은 실행을 이유와 함께 stuck으로 표시하고 리드가 다시 시킵니다. 컴퓨터가 꺼져 있어서 놓친 예약 회차는 한 번 돌고 `late`로 표시됩니다.

코드: `src/artemis/home.py`(`Paths`, `Home`, `open`, 잠금과 포트 파일), `src/artemis/supervise.py`(작업마다 감독자 하나), `src/artemis/schedule.py`(30초 주기와 회차 선점), `src/artemis/process.py`(자식 프로세스 환경과 프로세스 트리 전체 종료).

## 유일한 상태인 장부

장부는 SQLite 파일 하나, `~/.artemis/ledger.db`입니다. Artemis가 아는 모든 것이 여기 있습니다. 프로젝트, 사람이 쓴 그대로의 메시지와 요청, 작업과 기준, 실행, 제출, 근거, 판정, 카드, 계속 허용, 교훈, 예약, 백그라운드 작업, 기기, 영수증, 비밀값 사용 기록(이름과 시각만, 값은 없음)입니다.

두 종류의 기록이 있습니다. **테이블**은 지금 상태를 담습니다. **이벤트**는 추가만 되는 이력입니다. 상태가 바뀔 때마다 같은 트랜잭션에서 이벤트를 쓰고, 트리거가 이벤트의 수정과 삭제를 거부합니다.

사람이 보는 모든 것은 이 행들을 보여 주는 **화면**입니다. 앱, 보드, 상태 줄, 요약, `artemis show`. 어느 것도 따로 상태를 갖지 않습니다. 그래서 리드를 포함한 모든 세션을 버려도 됩니다.

코드: `src/artemis/ledger.py`에 테이블, 이벤트, 트리거, 그리고 작업마다 현재 상태 하나를 주는 `work` 뷰가 있습니다. 전이마다 쓰기 트랜잭션을 하나 열고, 사람의 정지와 행위자의 역할을 확인하고, 변경과 이벤트를 함께 저장합니다. 누가 어떤 전이를 할 수 있는지는 `src/artemis/roles.py`에 있습니다.

## 리드

사람은 에이전트 하나와 대화합니다. 리드는 사람의 말을 작업으로 바꾸고, 누가 맡을지 고르고, 모든 프로젝트를 따라가고, 무엇이 바뀌었는지 알려 줍니다.

리드는 매번 새로 시작합니다. 사람의 메시지 하나, 홈의 깨우기 하나(작업이 반영됐거나 막혔을 때, 카드에 답이 왔을 때, 예약이 돌았을 때)마다 헤드리스 턴을 새로 하나 엽니다. 홈은 장부에서 새로 읽은 맥락 묶음을 건넵니다. 프로젝트와 각 프로젝트가 지금 하는 일, 열린 카드, 다가온 예약, 범위 안의 교훈, 리드가 최근 남긴 메모, 마지막 메시지 20개입니다. 이어 붙일 벤더 세션은 없습니다. 그래서 두 메시지 사이에 리드 모델을 바꿔도 다음 턴은 두 프로젝트를 다 압니다. 리드의 기억은 대화 기록이 아니라 장부입니다.

리드에게는 자기 셸도 파일 도구도 없습니다. 리드의 도구는 관문의 리드 도구입니다. 프로젝트·상태·근거 읽기, 파일 읽기, 작업 만들기·다시 시키기·포기하기, 예약, 카드 묻기, 비밀값 요청, 교훈이나 메모 쓰기입니다. 자격 검사를 통과한 제공자는 누구나 리드가 될 수 있고, 여기서 누가 통과했는지는 `artemis doctor providers`가 알려 줍니다. 홈은 리드가 스스로 깨어나는 횟수를 제한합니다(`wake_per_hour`, 기본 6).

코드: `src/artemis/lead.py`(`LeadRunner`, 메시지나 깨우기마다 한 턴), `src/artemis/packet.py`(맥락 묶음), `src/artemis/templates/lead.md`(리드 지시문).

## 관문 하나

리드든 작업자든 모든 에이전트는 문 하나로만 컴퓨터에 닿습니다. 각 벤더의 자체 셸과 파일 도구는 꺼 두고, 에이전트는 MCP로 Artemis 도구를 받습니다. `artemis mcp --run <token-file>`은 작은 stdio 서버로, 호출마다 홈에 넘기고 홈이 실행합니다. 토큰이 실행을 가리키고, 홈은 그 실행이 무엇을 할 수 있는지 찾아봅니다.

관문은 호출을 실행하기 전에 사람의 정지를 확인하고, 모든 경로가 프로젝트가 등록한 폴더 안인지 확인하고, 명령을 규칙에 대 보고, 비밀값을 이름으로 넣고, 결과에서 금고의 모든 값을 지웁니다. 그리고 호출을 기록합니다.

작업자 도구: `run`, `job`, `job_stop`, `http_request`, `read_file`, `list_dir`, `search`, `write_file`, `move`, `trash`, `secret_names`, `secret_request`, `ask`, `note`, `check`. 리드 도구: `projects`, `status`, `evidence`, `read_file`, `list_dir`, `search`, `task_create`, `task_retry`, `task_drop`, `schedule`, `ask`, `secret_request`, `lesson`, `note`.

- `run`은 프로그램과 인자를 받고, 셸 한 줄은 받지 않습니다(프로젝트를 `--shell`로 추가했을 때만 예외). 45초까지 돌고 그 뒤에는 백그라운드 `job`이 됩니다.
- `http_request`는 에이전트 대신 웹 요청을 보냅니다. 웹사이트용 키는 홈이 그 사이트의 출처로 갈 때만 붙이므로, 어떤 에이전트 프로세스도 그 값을 받지 않습니다.
- `write_file`, `move`, `trash`는 바꾼 것을 기록합니다. 아무것도 지우지 않습니다.

벤더마다 울타리를 치는 방법:

| 에이전트 | 울타리 |
|---|---|
| Claude Code | `claude -p --restricted --strict-mcp-config`, 내장 도구는 워크트리 안의 읽기·편집만, 리드와 호스트 작업은 내장 도구 없음, MCP 서버는 Artemis 하나뿐 |
| Codex | `codex exec`, 셸 도구와 나열된 기능은 끔, 모드에 따른 OS 샌드박스, 지시는 stdin으로 |
| Gemini CLI | 실행마다 따로 두는 홈과 시스템 설정, Artemis 도구 말고 모든 내장 도구를 거부하는 관리자 정책 |
| OpenCode | `OPENCODE_CONFIG_CONTENT`로 넘기는 거부 우선 에이전트, 프로젝트 자체 설정은 무시 |
| API | 홈이 직접 돌리는 도구 루프, 모델은 Artemis 도구만 봄 |

울타리는 가정하지 않고 확인합니다. `artemis doctor providers`는 설치된 에이전트를 역할마다 한 번씩, 버려도 되는 검사장에서 돌립니다. 저장소 하나, 폴더 하나, 둘 다의 바깥에 무작위 표식을 넣어 둔 파일 하나, 방문을 기록하는 웹 페이지 하나, 호출을 기록하는 대역 도구 서버 하나입니다. 모델에게 울타리가 막아야 할 일을 시켜 보고, 검사는 그 뒤에 직접 볼 수 있는 것만 믿습니다. 모든 검사가 지켜지고 Artemis 호출이 하나 통과해야 그 역할에서 `live`입니다. 검사가 하나라도 깨지면 `unqualified`이고 배치에서 쓰지 않습니다. 계약대로 만들었지만 이 컴퓨터에서 실제로 보여 주지 않았으면 `contract`입니다. 새 버전이 나오면 다시 검사할 때까지 `live`가 `contract`로 돌아갑니다.

코드: `src/artemis/broker.py`(도구와 검사), `src/artemis/mcp.py`(stdio 서버), `src/artemis/guard.py`(명령을 규칙에 대 보기), `src/artemis/httpop.py`(`http_request`), `src/artemis/undo.py`(기록), `src/artemis/agents.py`와 `src/artemis/worker_adapters.py`(벤더마다 울타리 안에서 시작하기), `src/artemis/qualify.py`(자격 검사).

## 사람에게 오는 것

사람에게 오는 행동은 세 가지뿐입니다.

- **돈이 나가는 일**: 결제, 구매, 유료 요금제
- **되돌릴 수 없는 삭제**: 복구할 수 없는 모든 것
- **나 대신 보내는 일**: 사람의 이름으로 게시, 글쓰기, 메일, push

선은 되돌릴 수 없음과 남의 이름으로 하는 행동에 그었습니다. 시스템이 스스로 고칠 수 없는 실수가 그것이기 때문입니다. 그 선 아래에서 묻는 것은 주의력을 쓰고, 읽지 않고 승인하는 습관을 들입니다.

Artemis는 이런 행동을 세 가지로 알아보고, README는 어느 부분이 무엇인지 밝힙니다.

1. **행동이 쓰는 키로.** 비밀값은 종류와 함께 저장됩니다. `spend` 키는 쓸 때마다 '돈 나감' 카드가 되고, `send` 키는 무언가를 바꾸는 요청마다 '나 대신 보내기' 카드가 됩니다. 자격 증명이 금고에만 있는 한 지켜집니다.
2. **Artemis 자체 파일 도구로.** 지우지 않습니다. `trash`는 파일을 작업의 되돌리기 폴더로 옮깁니다.
3. **명령 패턴 목록으로.** `~/.artemis/rules.toml`에 있고 프로그램과 인자로 맞춰 봅니다. 이것은 경보선입니다. 목록이 모르는 프로그램은 실행됩니다. `--no-run`으로 추가한 프로젝트, `[run] wrap`의 샌드박스, 별도 OS 사용자가 이것을 벽으로 바꿉니다.

걸린 행동은 정확한 작업이 기록된 카드가 됩니다. 승인하면 그 기록된 작업이 관문을 거쳐 한 번 실행되고, 다시는 실행되지 않습니다. 사람이 카드를 내버려 두면 아무것도 바뀌지 않고 다른 일은 계속됩니다. 사람이 시킨 반복 전송은 카드에서 계속 허용을 고를 수 있습니다. 그 허용은 예약 하나, 정확한 주소 하나, 키 하나에 묶이고 언제든 취소할 수 있으며, 돈이 나가는 일에는 주어지지 않습니다. 카드는 선택지와 비밀값 요청도 나릅니다. 사람만 줄 수 있는 나머지 두 가지입니다.

나머지는 리드의 일입니다. 판정에서 떨어진 결과, 실패한 검사, 병합 충돌, 비정상 종료, 거부된 호출은 요약에 `stuck`으로 보이고, 리드가 다시 시키거나 포기합니다.

**정지**는 반대 방향으로 작동합니다. `artemis stop`(또는 앱의 정지 버튼)은 장부에 정지를 씁니다. 감독자, 예약, 재시도, 관문, 반영 경로는 단계마다 정지를 확인하고, 돌던 일은 끝냅니다. 정지를 푸는 것은 사람의 `artemis resume`뿐입니다.

코드: `src/artemis/roles.py`가 세 종류를 `Interrupt`로 정합니다. 패턴은 `src/artemis/guard.py`와 `src/artemis/templates/rules.toml`에, 카드·계속 허용·정지는 `src/artemis/ledger.py`의 전이로 있습니다. 승인된 카드를 정확히 한 번 실행하는 것은 `src/artemis/broker.py`의 `Broker.run_card`입니다.

## 비밀값

값은 `~/.artemis/vault.db`에 하나씩 AES-256-GCM으로 암호화해 둡니다. 금고 키는 `keyring`으로 OS 키체인에 둡니다. 키체인이 없거나 `[vault] unlock = "passphrase"`면, 홈을 켤 때 사람이 입력하는 암호 문구(scrypt)로 키를 감쌉니다. `unlock = "env"`는 CI용으로 환경 변수에서 읽습니다. 키 파일은 없습니다.

값은 숨김 입력(`artemis secret set`)이나 앱의 비밀값 카드로만 들어오고, 에이전트는 이름과 사람이 적은 메모만 봅니다. 웹사이트용 키는 `http_request`로만, 그 출처로만 나갑니다. 명령용 키는 그 명령의 환경 변수나 stdin으로 넘어가고 인자로는 넘어가지 않습니다. 그 뒤로 명령은 그 값으로 무엇이든 할 수 있다는 점을 README가 분명히 적습니다.

지우개는 저장된 모든 값과 흔한 인코딩(base64, base64url, hex, 퍼센트, JSON, 줄바꿈 변형, 더 긴 인코딩 속의 base64)을 도구 결과, 로그, 장부 글에서 `[secret:NAME]`으로 바꿉니다. `artemis secret audit`는 장부, 로그, 워크트리에서 모든 값을 찾아 몇 개가 나왔는지 알려 줍니다.

코드: `src/artemis/vault.py`, `src/artemis/scrub.py`, `src/artemis/httpop.py`.

## 호스트 작업과 되돌리기

호스트 작업은 폴더 프로젝트의 작업입니다. 작업자는 관문으로만 읽고, 쓰고, 실행합니다. '전체 제어'의 뜻은 이렇습니다. 사람이 직접 돌릴 수 있는 프로그램을, 그 사람으로서, 등록한 폴더에서 돌립니다. Artemis는 마우스를 움직이거나 화면을 읽지 않습니다.

`write_file`, `move`, `trash`는 바꾼 것을 `undo/task-N/`에 목록과 함께 남깁니다. `artemis undo N`은 최근 것부터 모두 되돌리고, 작업 뒤에 다시 바뀐 파일이 있으면 그 파일 이름을 대며 거부합니다. `run`으로 시작한 프로그램이 스스로 한 일은 이 기록 밖입니다.

호스트 작업이 시작될 때 감독자는 선언된 입력의 이름, 크기, 해시를 찍어 둡니다. 그다음 판정자는 사람도 확인할 수 있는 속성으로 판단합니다. 명령이 0으로 끝나는지, 파일이 있고 바뀌었는지, 파일에 어떤 글이 있는지, 폴더에 파일이 N개 이상인지, 모든 파일의 해시가 한 곳에서 다른 곳으로 그대로 옮겨졌는지입니다.

코드: `src/artemis/undo.py`, `src/artemis/judge.py`의 `snapshot`과 `capture`.

## 근거와 판정자

일을 한 에이전트가 끝났는지를 정하지 않습니다. 판정자가 정하고, 판정자는 기록된 것으로만 판단합니다.

작업마다 기준이 있습니다. 명령 기준은 작업자 커밋의 깨끗한 체크아웃(호스트 작업이면 그 폴더)에서 명령이 0으로 끝나면 충족됩니다. 파일 기준은 파일의 해시를 기록합니다. 근거는 작업자가 아니라 감독자가 직접 확보합니다. 작업자의 주장은 남기지만 무게는 없습니다. 판정자는 통과, 못 채운 기준을 단 거절, 판단할 수 없을 때의 중단 중 하나를 냅니다.

두 번째 의견을 청할 수도 있습니다(`review = true`). 작업자와 다른 회사 모델이 맡고, 빠진 점을 더할 수만 있습니다. 판정자가 떨어뜨린 작업을 통과시킬 수는 없습니다.

사람이 읽는 모든 줄은 어떻게 아는지를 밝힙니다.

| 표시 | 뜻 |
|---|---|
| `shipped` | 병합 결과에서 검사를 통과한 뒤 대상 브랜치에 들어감 |
| `verified` | 판정자가 근거를 통과시킴. 호스트 작업은 이것이 결과 |
| `reported` | 작업자가 그렇다고 함. 아직 확인 안 됨 |
| `inferred` | 리드의 해석 |
| `decided` | 사람이 카드에 답함 |
| `running` | 작업자가 지금 하는 중 |
| `stuck` | 리드가 처리하는 중 |

코드: `src/artemis/judge.py`, `src/artemis/review.py`. 표시는 `src/artemis/attention.py`에서 계산합니다.

## 반영 경로

코드는 한 길로만 대상 브랜치에 들어갑니다.

1. 판정받은 커밋을 고정해서, 확인한 것이 정확히 들어가게 합니다.
2. 사람의 정지를 확인합니다.
3. 버리는 워크트리에서 커밋을 지금의 대상 위에 병합합니다.
4. 그 병합 결과로 프로젝트 검사를 돌립니다.
5. **통과:** 3단계 뒤로 대상이 움직이지 않았을 때만 대상을 검사한 커밋으로 옮기고 영수증을 남깁니다.
6. **실패나 충돌:** 대상은 그대로 두고 이유를 작업의 감독자에게 돌려보냅니다. 감독자는 그 이유를 붙여 세 번까지 다시 시킵니다.

반영은 프로젝트마다 하나씩 차례로 합니다. Artemis는 스스로 push하지 않습니다. `git push`는 '나 대신 보내기'입니다.

코드: `src/artemis/ship.py`.

## 팀

일할 수 있는 에이전트는 다섯 종류입니다. Claude Code, Codex, Gemini CLI, OpenCode, OpenAI 호환 API이고, 데모와 CI용으로 표시된 모의 작업자가 있습니다. 작업마다 종류(code, review, research, docs, host)가 있고, `config.toml`의 `[placement]`가 종류마다 제공자 순서를 정합니다. 자격이 있고 쓸 수 있는 첫 번째가 맡습니다. 여럿이 동시에 돌고, 각자 자기 워크트리나 자기 실행 토큰 아래에서 일합니다.

배치도 배웁니다. 한 프로젝트에서 한 제공자가 같은 종류의 일을 세 번 실패하면, 배치 교훈이 그 프로젝트의 그 종류에서 그 제공자를 맨 뒤로 보냅니다.

Artemis는 사람이 설치한 CLI를 손대지 않고, 각 CLI가 관리하는 로그인으로 돌리며, 그 자격 증명을 읽지 않습니다. API 작업자는 제공자가 따로 요금을 매기므로 사람이 지정할 때만 돕니다.

코드: `src/artemis/agents.py`(`place`, `launch`, `available`), `src/artemis/worker_adapters.py`, `src/artemis/api_worker.py`, `src/artemis/mock_worker.py`, `src/artemis/qualify.py`.

## 교훈

실수는 다음 사과가 아니라 다음 실행을 바꿔야 합니다. 교훈은 종류, 범위(프로젝트 하나 또는 전체), 원인 이벤트, 카운터 두 개를 가진 장부의 한 행입니다.

- **계기.** 판정 거절 뒤의 통과와, 사람이 채팅에서 바로잡은 말은 리드가 교훈으로 씁니다. 한 제공자가 한 종류의 일을 세 번 실패하면 배치 교훈이 됩니다. 사람이 거절한 카드는 제안된 guard가 됩니다. 작업자는 교훈을 쓸 수 없습니다.
- **변화가 되는 방식.** `rule`은 그 범위의 다음 지시에 들어가는 한 줄입니다(최신 10개). `check`는 지금 대상에서 통과하고 그 교훈을 낳은 거절된 제출에서 실패할 때만 프로젝트 검사가 됩니다. `placement`는 제공자 순서를 바꿉니다. `guard`는 `rules.toml`의 새 패턴이고, 사람이 "앞으로도 … 전에 물어볼까요?"에 예라고 할 때만 들어갑니다.
- **보이게.** 요약에 `learned L4 … from #12 judge reject`가 뜨고, 교훈마다 쓰인 횟수와 그 뒤 첫 시도 통과 횟수를 셉니다. 다섯 번 쓰였는데 프로젝트의 첫 시도 통과율을 넘지 못한 교훈은 `unproven`으로 표시됩니다.
- **푸는 것은 사람만.** 교훈은 사람이 앱이나 `artemis lesson`으로 내립니다. Artemis는 설치된 자기 코드를 고치지 않습니다. 코드 변경은 평범한 작업, 판정자, 반영 경로를 거칩니다.

`tests/test_lessons.py`가 이 구조를 보여 줍니다. 정해진 대로 움직이는 작업자가 실패하고, 교훈이 생기고, 다음 작업은 첫 시도에 통과하고, 교훈을 내리면 다시 실패합니다.

코드: `src/artemis/lessons.py`.

## 앱

앱은 사람이 주로 쓰는 화면이고, 홈이 `src/artemis/web/`에서 서비스합니다. 표준 라이브러리 HTTP 서버에 서버 전송 이벤트와 롱 폴링 대체 경로가 있고, 프런트엔드는 Preact와 htm을 함께 넣은 평범한 모듈이라 빌드 단계가 없습니다.

화면: 리드와의 대화(카드는 생긴 자리와 '내 차례' 모음에 함께 뜹니다), 모든 프로젝트의 보드, 요약, 교훈, 비밀값(이름, 종류, 출처, 마지막 사용. 값은 없음), 설정(에이전트, 배치, 계속 허용, 기기, 예약). 정지와 재개는 모든 화면에 있습니다. 머리글은 `asked you 1× today · 7 done · 0 stuck`처럼 횟수를 늘 보여 줍니다.

이 컴퓨터에서는 루프백 주소와 토큰으로 서비스합니다. `--lan`은 HTTPS로만 서비스하고, 인증서는 홈이 직접 만든 자체 서명 인증서입니다. 터미널에 주소, QR 코드, 지문이 나옵니다. 연결 링크는 한 번만, 잠깐만 쓸 수 있습니다. 찍고 나면 폰에 숫자 4자리가 뜨고, 사람이 컴퓨터에서 그 숫자를 확인해야 폰이 권한을 얻습니다. 기기는 목록을 보고 내보낼 수 있습니다.

코드: `src/artemis/web/`(`__init__.py`가 서버와 API, `index.html`·`app.js`·`chat.js`·`cards.js`·`board.js`·`pages.js`가 화면, `vendor/`에 Preact와 htm과 그 라이선스), `src/artemis/tls.py`(인증서와 QR 코드).

## 요약

요약은 사람이 따라잡는 방법입니다. 기간, 횟수, 막힌 것이 있는지를 담은 머리 한 줄, 그리고 손댄 작업과 결정한 카드마다 한 줄씩입니다. 줄마다 표시로 시작해서 근거로 끝납니다.

```text
Last 1 min · asked you 1× · 3 done · 0 stuck · 0 wakes
shipped   #1 Add a --json flag                 main 0796fa7 · python3 -m unittest exit 0
shipped   #2 Add a --done filter               main b319430 · python3 -m unittest exit 0
shipped   #3 Document both in the README       main e0dff1f · README mentions --json, --done
decided   D1 POST to the local demo receiver   you approved · 204 No Content · body matches the card
```

사람이 읽었을 때만 그 기간을 읽은 것으로 표시합니다.

코드: `src/artemis/attention.py`(`digest`, `status`, `statusline`).

## 실패를 다루는 법

무언가 실패하면 고칠 곳은 실패가 나온 곳입니다. 에이전트를 다룰 때의 반사 신경은 문제가 보인 자리에 방어를 하나 더하는 것입니다. 재시도, 대기, 특별 처리, 프롬프트 한 줄. 하나하나는 한동안 통하지만, 모이면 아무도 이해할 수 없는 시스템이 됩니다. Artemis는 설계의 무엇이 그 실패를 낳았는지 묻고 그것을 바꿉니다. 교훈 루프는 시스템이 자기 실수에도 같은 일을 하게 하려고 있습니다.

실패는 삼키지 않고 기록합니다. 실패한 검사는 출력 해시를 가진 행이고, 막힌 작업은 이유를 들고 있고, 거부된 호출은 이벤트이며, 요약이 그것들을 보여 줍니다.

## 빠진 것

Artemis는 더 큰 개인 시스템에서 시작했습니다. 이 저장소는 그 공개판을 새로 쓴 것이고, 일부는 일부러 뺐습니다.

- **화면·마우스 조작.** 호스트 작업은 프로그램을 돌리고, 데스크톱을 조작하지 않습니다.
- **OS 서비스.** 홈은 `artemis serve`가 도는 동안 돕니다.
- **여러 사용자, 푸시 알림, 네이티브 앱.**
- **스스로 고치기.** 교훈은 프롬프트, 검사, 배치, 규칙을 바꾸고, Artemis의 설치된 코드는 바꾸지 않습니다.
- **실제 데이터.** 코드, 테스트, 데모의 요청, 작업, 이름은 모두 지어낸 것입니다.
